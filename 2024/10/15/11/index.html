【Vue】原来生命周期这么有生命感
Published in：2024-10-15 |

Vue 生命周期全解析：从生命诞生到轮回的组件史诗

之前一直不知道生命周期为什么叫生命周期，今天才知道，它就像人类的一生被编码进了数字世界。经历了诞生（Creation）、成长（Mounting）、适应（Updating）、死亡（Destruction）。这个过程，就像是把我们人类的生命经历，用另一种方式在数字世界里重新演绎了一遍，让人觉得既奇妙又亲切。

一、生命诞生篇（Creation）

1. beforeCreate

如同宇宙初开的星云，组件仅有基础框架。数据观测和事件系统尚未形成。

  • 技术本质
    组件实例目前仅有基础结构，此时数据观测（data）、事件监听（methods）均未初始化，无法访问任何响应式数据。常用于插件开发中的基础配置初始化
  • 典型场景
    插件基础配置（如Vuex状态注入）

2. created

完成初步构建，data 响应式化（血液流动），但未与 DOM 世界连接。

  • 技术本质
    数据响应式化（data、methods 就绪），但尚未与 DOM 建立联系。此时可发起异步请求、计算属性初始化，是数据获取的黄金时机。
    注意：操作 DOM 需通过 this.$nextTick 等待。
  • 典型场景
    发起 API 请求（如加载用户数据）
    初始化非 DOM 依赖的第三方库
    数据预处理（如时间格式化）

二、成长觉醒篇（Mounting）

3. beforeMount

虚拟 DOM 已编织成茧，但真实 DOM 仍是未孵化的蛹（如 {{data}} 占位符）。

  • 技术本质
    虚拟 DOM 已编译完成，但真实 DOM 仍为占位符状态（如 ）。此时可修改模板逻辑，但直接操作 DOM 无效。Vue 按 render > template > outerHTML 优先级选择模板。
  • 典型场景
    预加载静态资源（如多语言模板）
    修改模板渲染逻辑

4. mounted

组件已挂载到 DOM 树梢，$el 可操作（如初始化图表库）。

  • 技术本质
    组件正式挂载到页面，$el 可操作。适合初始化第三方库（如 ECharts）、绑定事件监听或执行依赖 DOM 的操作
  • 典型场景
    初始化 ECharts/D3 图表
    绑定滚动/窗口大小监听事件
    操作 DOM 节点（如聚焦输入框）

三、适应进化篇（Updating）

5. beforeUpdate

数据变化如气象突变，虚拟 DOM 重建避难所，真实 DOM 仍平静。

  • 技术本质
    数据变化触发更新流程，此时 DOM 尚未重新渲染。可捕获更新前的状态，用于对比或记录快照 。若在此阶段修改数据，不会触发额外更新，避免无限循环 。
  • 典型场景
    记录更新前的滚动位置
    对比新旧数据差异

6. updated

DOM 与数据完成同步，可重置轮播图或调整布局。

  • 技术本质
    DOM 已同步最新数据，可操作更新后的元素。常用于调整布局或更新依赖 DOM 的插件（如轮播图重置）
  • 典型场景
    调整动态布局（如瀑布流重排）
    重置轮播图/动画状态

四、生命轮回篇（Destruction）

7. beforeDestroy

组件即将销毁，需清理定时器、解绑事件。

  • 技术本质
    实例仍完整可用，但即将销毁。需清理定时器、解绑全局事件（如 window.resize）、取消网络请求，防止内存泄漏。关闭 WebSocket 连接或清除本地存储的临时数据。
  • 典型场景
    关闭 WebSocket 连接，清除临时数据。
    移除 window.addEventListener 事件
    清除定时器（setInterval）

8. destroyed

实例销毁，DOM 墓碑仍存，需手动移除节点。

  • 技术本质
    实例完全销毁，所有子组件和监听器被移除。但 DOM 元素仍存在，需手动清理（如父组件移除子节点）
  • 典型场景
    父组件手动移除 DOM 节点（v-if 控制）
    释放内存占用

五、特殊生命形态

9. activated/deactivated

  • 技术本质
    用于 keep-alive 缓存的组件，实现状态保留与恢复。如返回页面时刷新数据（activated），离开时暂停视频播放（deactivated）
  • 典型场景
    activated：返回页面时刷新数据
    deactivated：离开页面时暂停视频播放

10. errorCaptured（生命救护）

  • 技术本质
    捕获子孙组件的错误，可用于统一错误上报或优雅降级处理
  • 典型场景
    上报错误日志到监控平台
    显示降级 UI（如错误提示页）

生命周期整体流程

beforeCreate -> created

  • beforeCreate
    初始化 Vue 实例，进行数据观测。
  • created
    完成数据观测，属性与方法的运算，watch、event 事件回调的配置。
    可调用 methods 中的方法，访问和修改 data 数据触发响应式渲染 DOM，可通过 computed 和 watch 完成数据计算。
    此时 vm.$el 并没有被创建。

created -> beforeMount

  • 判断是否存在 el 选项，若不存在则停止编译，直到调用 vm.$mount(el) 才会继续编译。
    优先级：render > template > outerHTML。
    vm.el 获取到的是挂载 DOM 的。

beforeMount

  • 在此阶段可获取到 vm.el。
    此阶段 vm.el 虽已完成 DOM 初始化，但并未挂载在 el 选项上。

beforeMount -> mounted

  • 此阶段 vm.el 完成挂载，vm.$el 生成的 DOM 替换了 el 选项所对应的 DOM。

mounted

  • vm.el 已完成 DOM 的挂载与渲染，此刻打印 vm.$el，发现之前的挂载点及内容已被替换成新的 DOM。

beforeUpdate

  • 更新的数据必须是被渲染在模板上的（el、template、render 之一）。
    此时 view 层还未更新。
    若在 beforeUpdate 中再次修改数据，不会再次触发更新方法。

updated

  • 完成 view 层的更新。
    若在 updated 中再次修改数据，会再次触发更新方法（beforeUpdate、updated）。

beforeDestroy

  • 实例被销毁前调用，此时实例属性与方法仍可访问。

destroyed

  • 完全销毁一个实例。可清理它与其它实例的连接，解绑它的全部指令及事件监听器。
    并不能清除 DOM，仅仅销毁实例。

六、开发者心法

  1. 生命节奏法则
    数据请求宜早（created），DOM 操作宜迟（mounted）。
  2. 生态平衡原则
    更新阶段慎改数据，销毁阶段必清资源。
  3. 永生之道
    善用 keep-alive 实现“数字永生”。

组件的一生是代码书写的史诗，每个 console.log 是心跳，每次 this.$emit 是对话。理解生命周期，便是领悟 Vue 的生生不息。
